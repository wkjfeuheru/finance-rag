# 合规文本审查测试用例

> 用途：调用 `POST /api/compliance/review`。
> `expected_*` 字段是验收参考，不是模型输入。

## TC-TEXT-001：合规营销文案

- 输入类型：text
- 难度：easy
- 预期风险：safe
- 预期动作：pass
- 预期命中规则：无
- 证据要求：若报告判定为 safe，应说明未发现红线，且不得生成虚构法规条款

### 输入文本

本产品面向符合风险承受能力要求的投资者发行。产品不承诺保本或固定收益，投资者应在购买前认真阅读产品说明书和风险揭示书，并根据自身情况独立作出投资决策。

## TC-TEXT-002：保本保息与高额回报承诺

- 输入类型：text
- 难度：easy
- 预期风险：unsafe
- 预期动作：reject
- 预期命中规则：RL-002
- 预期原文证据：保本保息；承诺高额回报
- 证据要求：每个违规点必须引用输入文本原文，并绑定包含对应法规依据的法规证据；无法绑定时降级为 controversial/manual_review

### 输入文本

本项目面向社会公众募集资金，承诺本金绝对安全、保本保息，预计年化收益率达到 18%，并承诺高额回报，投资者无需承担任何风险。

## TC-TEXT-003：未经许可开展金融业务

- 输入类型：text
- 难度：easy
- 预期风险：unsafe
- 预期动作：reject
- 预期命中规则：RL-001
- 预期原文证据：未取得许可；擅自从事金融业务
- 证据要求：finding 必须记录规则 ID、触发关键词、原文字符位置和法规 source/chunk

### 输入文本

公司目前尚未取得相关金融业务许可，但计划通过线上平台擅自从事金融业务，并向用户收取资金管理服务费。

## TC-TEXT-004：反洗钱义务缺失

- 输入类型：text
- 难度：medium
- 预期风险：unsafe 或 controversial
- 预期动作：reject 或 manual_review
- 预期命中规则：RL-003
- 预期原文证据：客户身份识别不到位；未按规定报告可疑交易
- 证据要求：若法规知识库没有对应条款，不能直接输出 confirmed unsafe，应转人工审核

### 输入文本

由于业务量较大，平台暂不执行客户身份识别，也不对异常资金流进行持续监测；发现可疑交易时无需按规定向有关部门报告。

## TC-TEXT-005：证券营销误导表述

- 输入类型：text
- 难度：medium
- 预期风险：unsafe 或 controversial
- 预期动作：reject 或 manual_review
- 预期命中规则：RL-005
- 预期原文证据：夸大收益；隐瞒风险；误导投资者
- 证据要求：至少逐项列出营销表述问题，并为每项绑定法规原文证据

### 输入文本

该产品收益稳定且几乎没有风险，过去一年收益率远超同类产品。宣传页面无需展示可能亏损的情形，以免影响客户购买决策。

## TC-TEXT-006：法规依据不足的灰色案例

- 输入类型：text
- 难度：hard
- 预期风险：controversial
- 预期动作：manual_review
- 预期命中规则：无或不确定
- 证据要求：报告必须明确列出缺少的法规类型，不得将无法判断解释为 safe

# 基于合规风控文档的规则反推用例

> 以下用例刻意不直接使用内置 `RL-001` 至 `RL-005` 的关键词，审查时应依赖 `compliance_risk` 类知识库中的法规/制度文档完成规则反推。若法规证据不足，预期应为 `controversial/manual_review`，不能直接判定 safe。

## TC-TEXT-RULE-001：数据出境未建立实施细则

- 输入类型：text
- 参考合规文档：银行保险机构数据安全管理办法.pdf
- 预期风险：controversial 或 unsafe
- 预期动作：manual_review 或 reject
- 反推规则主题：涉及境外数据流动时，应制定数据出境安全管理实施细则
- 预期原文证据：将境内客户交易明细直接同步至境外分析平台；未制定专项安全管理实施细则
- 证据要求：法规证据必须回指具体 source/chunk 和条款原文

### 输入文本

为提升海外团队的分析效率，项目上线后将境内客户交易明细实时同步到境外分析平台。当前方案没有单独的数据出境安全管理实施细则，也未明确审批、风险评估和留痕责任。

## TC-TEXT-RULE-002：委托终止后未销毁数据

- 输入类型：text
- 参考合规文档：银行保险机构数据安全管理办法.pdf
- 预期风险：controversial 或 unsafe
- 预期动作：manual_review 或 reject
- 反推规则主题：委托数据处理终止时，应要求服务商删除数据并确保不可恢复
- 预期原文证据：合作结束后保留客户数据备份；不要求服务商删除
- 证据要求：至少生成一个 finding，同时绑定业务描述原文和法规条款原文

### 输入文本

外包数据处理合同到期后，服务商可以继续保留历史客户数据和备份文件，便于未来重新合作。公司不要求服务商删除数据，也不安排销毁结果的核验。

## TC-TEXT-RULE-003：名单命中后继续办理业务

- 输入类型：text
- 参考合规文档：反洗钱特别预防措施管理办法.pdf
- 预期风险：unsafe 或 controversial
- 预期动作：reject 或 manual_review
- 反推规则主题：客户或交易对象命中名单后，应立即采取反洗钱特别预防措施
- 预期原文证据：名单命中后继续办理转账；等待月末统一复核
- 证据要求：不能只因为未命中内置红线而判定 safe，必须展示法规检索证据或说明证据不足

### 输入文本

系统发现客户交易对象与重点名单存在匹配后，业务人员仍可先完成资金转账，待月底集中复核后再决定是否采取限制措施。

## TC-TEXT-RULE-004：第二道防线未参与重大流程审查

- 输入类型：text
- 参考合规文档：上海证券交易所交易规则（2026年修订）【2026年7月6日起施行】.pdf、银行保险机构数据安全管理办法.pdf
- 预期风险：controversial 或 unsafe
- 预期动作：manual_review 或 reject
- 反推规则主题：交易规则约束与数据安全控制应分别落实，跨境/交易相关业务不能绕过审批和留痕
- 预期原文证据：业务部门直接同步数据并绕过交易及安全控制
- 证据要求：法规证据必须区分交易规则和数据安全管理要求

### 输入文本

项目计划将境内客户交易明细直接同步到境外分析平台，同时允许交易员在系统校验失败时绕过前置控制、先提交申报，事后再补充审批和留痕。

## TC-TEXT-RULE-004：名单命中后继续办理业务

- 输入类型：text
- 参考合规文档：反洗钱特别预防措施管理办法.pdf
- 预期风险：unsafe 或 controversial
- 预期动作：reject 或 manual_review
- 反推规则主题：客户或交易对象命中名单后，应立即采取特别预防措施
- 预期原文证据：名单命中后继续办理转账；等待月末统一复核
- 证据要求：不能只因为未命中内置红线而判定 safe，必须展示法规检索证据或说明证据不足

### 输入文本

系统发现客户交易对象与重点名单存在匹配后，业务人员仍可先完成资金转账，待月底集中复核后再决定是否采取限制措施。

## TC-TEXT-RULE-005：交易异常处置缺失

- 输入类型：text
- 参考合规文档：上海证券交易所交易规则（2026年修订）【2026年7月6日起施行】.pdf
- 预期风险：controversial 或 unsafe
- 预期动作：manual_review 或 reject
- 反推规则主题：异常交易行为应接受监控并按要求处置、记录和报告
- 预期原文证据：关联账户短时间内反复成交和撤单；发现异常后不记录、不报告
- 证据要求：至少生成一个 finding，并绑定交易规则中的异常交易或监管处置证据

### 输入文本

策略允许多个关联账户在短时间内相互成交并反复撤回未成交申报，以制造活跃成交假象。监控人员发现后无需记录，也无需向交易所或内部合规部门报告。

## TC-TEXT-RULE-006：委托处理终止后继续留存数据

- 输入类型：text
- 参考合规文档：银行保险机构数据安全管理办法.pdf
- 预期风险：controversial 或 unsafe
- 预期动作：manual_review 或 reject
- 反推规则主题：委托数据处理终止后，应要求服务商删除或返还数据并确保不可恢复
- 预期原文证据：合同到期后保留客户数据和备份；不提供销毁证明
- 证据要求：报告需分别绑定服务商留存行为和数据销毁/返还要求

### 输入文本

外包数据处理合同到期后，服务商可以继续保留客户资料、日志和灾备副本三年。合同不要求服务商删除或返还数据，也不要求提供销毁结果证明。
