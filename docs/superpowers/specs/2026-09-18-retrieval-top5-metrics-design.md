# 检索层 Top-5 评估设计

## 目标

将检索链路评估收敛为基于现有评测集的三项指标：块级 Recall@5、Precision@5、MRR。移除 L4，并用互斥且可归因的配置比较稠密检索、混合检索、重排序及断崖检测。

## 层级与变量隔离

| 层 | 检索配置 | 对照目的 |
| --- | --- | --- |
| L0 | 纯稠密，未重排序 | 稠密基线 |
| L1 | 混合检索（RRF），未重排序 | 相对 L0 的混合检索增益 |
| L2 | 混合检索（RRF），未重排序 | 相对 L3 的重排序基线 |
| L3 | 混合检索（RRF）+ BGE 重排序，关闭断崖检测 | 相对 L2 的重排序增益；相对 L5 的断崖基线 |
| L5 | 与 L3 相同，但开启默认断崖检测 | 断崖检测的影响 |

L1 和 L2 的运行时检索参数相同；它们分别服务于两组明确的对照关系，结果应相同。所有层使用 `k=5` 评价；重排序层从同一候选池取得结果后仅以最终返回的前五块参与计算。

## 指标口径

- **块级 Recall@5**：每题 Top-5 检索块与标注证据块的交集数，除以该题标注证据块数；对有证据块标注的评测条目取平均。
- **Precision@5**：每题 Top-5 中命中标注证据块的数量，除以 5；不足 5 个返回结果仍以 5 为分母，避免断崖截断因返回更少而虚增精确率。
- **MRR**：首个命中标注证据块的倒数排名；Top-5 内未命中记 0。

负样本不含正例证据块，不进入以上三个正例检索指标的聚合。保留库中确实存在相关文档的条目；脚本继续明确报告被剔除条目与单题检索错误数。

## 实现边界

- 修改 `scripts/eval_recall.py`：重定义层级、禁用 L3 的断崖函数并为 L5 恢复默认断崖函数、计算和渲染仅三项指标及三组关键差值。
- 扩展 `tests/unit/test_eval_metrics.py`：覆盖 Precision@5 的固定分母、块级 MRR 和少于五条结果的边界。
- 不修改知识库数据、Milvus 索引、线上 API 或检索生产默认配置。

## 验收

1. 评估输出只包含 L0、L1、L2、L3、L5 及三项指定指标。
2. L3/L5 仅在断崖检测开关上不同，L2/L3 仅在重排序开关上不同。
3. 单元测试先证明原有实现不满足指标口径，再在实现后通过。
4. 用未抽样的有效评测条目实际连接 Milvus 跑完，并将原始输出保存为可复核结果。
